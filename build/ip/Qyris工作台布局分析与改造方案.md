# Qyris工作台布局分析与改造方案

## 一、文档概述
本文档针对 `Qyris` 开发工作台的界面布局进行全面拆解，系统分析现有三栏式布局的优缺点，并针对「左侧新增AI实时交互能力、右侧保留AI聊天面板」的产品需求，提供可落地的布局改造方案与通用优化建议。

## 二、当前布局结构详解
当前工作台采用**经典三栏式IDE布局**，顶部为全局Tab导航，整体遵循「左资源-中操作-右辅助」的交互逻辑，是面向AI辅助开发场景设计的一体化工作台。

### 2.1 整体框架
页面横向划分为三个固定功能区域，职责边界清晰：
- **左侧侧边栏**：项目资源管理、版本控制、用户记忆管理，负责工程上下文与静态资源管控
- **中间主工作区**：核心操作画布，通过顶部Tab切换不同工作模式，承载主要开发动作
- **右侧侧边栏**：AI助手对话面板，提供代码评审、需求问答等结对编程能力

### 2.2 左侧栏：项目与记忆管理
左侧栏为固定宽度的导航面板，支持视图切换，承载两类核心功能：
1.  **项目视图**
    - 顶部操作区：创建项目、打开项目入口
    - 项目列表：当前项目、历史项目展示
    - Git模块：分支切换、拉取/获取/推送操作、改动文件列表、暂存提交管理
2.  **用户记忆视图**
    - 记忆搜索、分类筛选（偏好/事实/事件/教训/技能/摘要）
    - 记忆的导入、导出、清空、重新整理功能

### 2.3 中间主工作区
中间区域为工作台核心画布，通过顶部Tab栏切换4种工作模式，无需跳转新页面：

| Tab名称 | 核心功能 |
|--------|----------|
| 文件 | 项目文件树浏览、全局文件搜索、代码编辑预览 |
| 预览 | AI编译、部署、运行状态监控，项目启动与停止控制 |
| 记忆 | 项目级记忆知识库管理 |
| 技能 | 自定义Skill导入与管理，扩展AI能力边界 |

### 2.4 右侧栏：AI助手面板
固定宽度的常驻对话面板，定位为AI结对编程助手：
- 顶部：服务状态指示灯、环境变量配置入口
- 主体：对话内容展示区，当前承载项目代码评审报告输出
- 底部：消息输入框、发送操作，支持API Key配置

## 三、当前布局优缺点分析

### 3.1 核心优点
1.  **工作流高度匹配AI开发场景**
    天然契合「浏览资源→编写代码→AI辅助评审」的开发流程，视线无需大范围跳转；中间区域通过Tab聚合多类操作，避免多窗口碎片化，符合前端开发者的IDE使用习惯，上手成本低。

2.  **功能模块化隔离，结构清晰**
    三区域职责边界明确：左侧管资源上下文、中间管执行操作、右侧管AI对话，功能分区不重叠；记忆、Git等特色能力深度内嵌工作台，无需切换外部工具即可完成全流程开发。

3.  **项目记忆体系差异化明显**
    将项目记忆作为一等功能模块，支持沉淀项目知识、与AI对话联动，适合长期项目迭代；同时提供项目级与全局级双视角，区别于普通AI代码插件。

4.  **布局扩展性良好**
    中间Tab可横向扩展新功能模块；左右侧边栏支持折叠改造，可灵活适配不同屏幕尺寸；左侧内部可通过新增Tab的方式扩展能力，无需重构整体骨架。

### 3.2 现存问题与缺点
1.  **横向空间占用高，小屏体验受限**
    三栏常驻布局对屏幕宽度要求较高，窄屏环境下中间代码编辑区被挤压，代码阅读与编辑体验下降；若后续新增AI面板，横向空间压力会进一步放大。

2.  **功能入口重复，存在认知割裂**
    `记忆`模块同时存在「左侧侧边栏入口」与「中间顶部Tab入口」，同一功能两个入口易造成用户困惑，提升认知成本。

3.  **左侧面板功能易臃肿**
    左侧栏已承载项目树、Git、记忆三类功能，若继续叠加AI实时交互，窄侧边栏会出现信息密度过高、Tab过多的问题，且窄区域不适合展示长文本内容。

4.  **中间Tab职责过重**
    文件编辑、编译预览、记忆管理、技能管理全部集中在中间Tab，功能持续增加后会导致Tab栏过长，高频切换会打断编码专注度。

5.  **AI能力与工程能力联动不足**
    右侧AI对话与左侧工程资源、Git变更为相互独立的面板，缺少快捷联动机制；例如代码报错无法一键发送给AI排查，打断开发工作流。

## 四、双AI面板布局改造方案
### 4.1 需求背景
在现有布局基础上，新增**左侧AI实时交互能力**，形成「左AI实时交互 + 中工程操作 + 右AI自由聊天」的双AI面板架构，同时满足实时工程洞察与自由对话的双重需求。

### 4.2 方案一：最小改动方案（推荐）
#### 改造思路
保留原有三栏整体骨架不变，在**左侧侧边栏内部新增Tab切换**，将AI实时交互作为左侧的一个视图，与项目、记忆、Git视图并列。

#### 布局结构
```
┌─────────────────────────────────────────────────────────────────────┐
│ 【顶部全局Tab导航】 文件 | 预览 | 记忆 | 技能                        │
├───────────────┬───────────────────────────────┬─────────────────────┤
│ 左侧侧边栏    │        中间主工作区           │   右侧AI聊天面板   │
│ ┌───────────┐ │                               │ ┌─────────────────┐ │
│ │Tab：AI交互│ │        文件树/预览运行        │ │ 自由对话区      │ │
│ │Tab：项目  │ │        【核心画布】           │ │ 输入框          │ │
│ │Tab：记忆  │ │                               │ └─────────────────┘ │
│ │Tab：Git   │ │                               │                     │
│ └───────────┘ │                               │                     │
└───────────────┴───────────────────────────────┴─────────────────────┘
```

#### 改造点
1.  左侧侧边栏新增「AI实时交互」Tab，可作为默认展示视图
2.  原有项目、记忆、Git功能全部收纳为左侧Tab，用户可按需切换
3.  中间主工作区、右侧AI聊天面板完全保留，无需改动

#### 双AI分工原则
- **右侧AI助手：主动对话**：用户主动发起提问，承载长文本问答、代码生成、完整项目评审等重交互场景
- **左侧AI实时交互：被动推送**：自动监听工程状态（文件打开、代码保存、编译报错、Git变更），实时输出摘要、告警、优化建议，无需用户主动输入

#### 方案优势
- 改动成本最低，整体页面骨架、CSS布局无需重构
- 功能可灵活切换，用户可按需调出项目/Git视图，不影响原有操作习惯
- 双AI面板分工明确，避免功能重复与认知混淆

#### 注意事项
左侧栏宽度有限，AI实时交互仅适合展示精简卡片、短提示、告警摘要，不适合展示长段落内容。

### 4.3 方案二：分栏重构方案
#### 改造思路
调整三栏宽度比例，加宽左侧面板作为独立AI实时交互区；将原有项目、Git、记忆功能全部整合进中间主工作区的Tab体系中。

#### 布局结构
```
┌─────────────────────────────────────────────────────────────────────┐
│ 顶部全局Tab： 文件 | 预览 | 项目资源 | 记忆 | 技能                    │
├──────────────────────┬──────────────┬───────────────────────────────┤
│ 左：AI实时交互面板   │ 中间：工程区 │ 右：AI聊天对话面板            │
│ （加宽）             │ 代码/预览    │（保持原有宽度）               │
└──────────────────────┴──────────────┴───────────────────────────────┘
```

#### 改造点
1.  调整三栏宽度占比，左侧面板加宽，作为专职AI实时交互区
2.  将原左侧的项目树、Git、记忆功能迁移至中间顶部Tab，与文件、预览并列
3.  右侧聊天面板保持原有宽度与功能不变

#### 方案优势
- 左侧AI交互区域空间充足，可承载更丰富的实时信息、日志、可视化内容
- 中间工程区Tab聚合所有资源管理功能，入口更统一

#### 方案劣势
- 改动量大，原有左侧模块全部需要迁移重构
- 中间Tab数量显著增加，Tab栏会更拥挤
- 打破了原有IDE式的操作习惯，用户学习成本更高

### 4.4 双AI面板联动设计建议
为避免两个AI面板相互孤立，建议增加联动能力：
1.  左侧实时告警/建议卡片，支持「发送到AI助手」快捷按钮，一键跳转右侧继续追问
2.  右侧AI对话生成的代码，支持一键应用到中间编辑区
3.  两侧AI共享同一份项目上下文与记忆库，无需重复说明项目背景

## 五、通用优化建议
1.  **侧边栏可折叠**：左右侧边栏均增加一键收起/展开按钮，窄屏环境下可隐藏任意一侧，最大化中间编辑区域
2.  **统一记忆入口**：移除重复的记忆入口，仅保留一处记忆管理入口，降低认知成本
3.  **Git面板优化**：Git模块默认收起，仅在有文件变更时提示，减少常驻空间占用
4.  **响应式适配**：针对小屏设备自动折叠侧边栏，优先保障中间代码编辑区的宽度
5.  **Tab可自定义**：支持用户自定义中间顶部Tab的显示与排序，适配不同工作流

## 六、总结
当前三栏式布局**天然适配大屏AI辅助开发场景**，结构清晰、工作流顺畅，具备良好的扩展性；核心痛点在于横向空间压力与部分功能入口冗余。

对于新增左侧AI实时交互的需求，**优先推荐方案一（最小改动方案）**，在保留原有布局骨架与操作习惯的前提下，以最低成本实现双AI面板架构，同时通过联动设计保障体验连贯性。后续可根据业务发展与用户反馈，逐步迭代响应式适配与功能优化。
